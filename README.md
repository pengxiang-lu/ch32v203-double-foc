# CH32V203 DOUBLE-FOC

<img src="README.assets/image-20261008102334351.png" alt="image-20261008102334351" style="zoom:44%;" /><img src="README.assets/image-20261008102319128.png" alt="image-20261008102319128" style="zoom:49%;" />

## 功能概览

- 左、右两路电机控制均在固件中启用，每路输出三相 PWM。
- 使用 MT6701 磁编码器读取电角度/机械角度；两路编码器共用 SPI2，通过独立片选读取。
- 固件包含开环、速度、角度及电流相关控制模式代码；实际可用模式受电机参数、传感器接线和 `driver_config.h` 配置影响。
- 支持 UART 双电机命令接收和状态数据回传。
- 固件包含电流采样、电池电压采样、按键零点校准和 LED 状态指示代码。
- 支持外部电源供电额定电压为12V。

当前源码默认配置为速度闭环、SVPWM-7、20 kHz 开环控制参数、14 位编码器精度、460800 baud 串口。注意：源码里的频率常量和定时器实际输出频率应结合系统时钟与定时器配置核算，不能只凭宏名作为实测值。

## 硬件与接线

照片能确认板上有 `VIN`、`GND` 和两组标记为 A/B/C 的电机相线接口。`VIN` 的允许电压、极性保护能力、每路最大电流以及接口对应左/右电机，请以原理图和 PCB 网络标注为准。接线前断开电源；首次调试请使用限流电源，并确保电机及负载固定可靠。

### 已知资料冲突

工程内的 `引脚定义.txt` 与实际源码存在多处不一致，需结合硬件原理图/PCB确认并统一：

- 引脚文档把六路 PWM 写为 PA8/PA9/PA10 和 PB13/PB14/PB15；`pwm_output.h` 实际配置为左侧 PB8/PB7/PB6、右侧 PA0/PA1/PA2。
- 引脚文档写 UART TX/RX 为 PA2/PA3；`Debug/debug.c` 初始化 USART1，并将 GPIO 配为 PA9/PA10。
- 引脚文档写电流采样 IA/IB/IC 为 PA0/PA1/PA7，且 Vin 也写 PA7；`driver_adc.c` 实际扫描 PA3 至 PA7，其中固件将前四个采样值用于两路电机 A/C 相电流，将第五个值用于电池电压读取。
- 引脚文档把按键写为 PB12；GPIO 代码实际使用 PA8，而 PB12 在编码器配置中是左编码器片选。

以上差异可能来自旧版文档、源码配置或硬件版本变化。应以对应 PCB 版本的原理图和实际板卡测量为准，并在使用前更新固件和文档。硬件工程位于 [`硬件原理图和PCB`](硬件原理图和PCB/)。

## 串口协议

串口参数：460800 baud、8 数据位、无校验、1 停止位（8-N-1）。二进制控制帧固定为 6 字节：

| 字节 | 内容 |
| --- | --- |
| 0 | 帧头 `0xA5` |
| 1-2 | 左电机有符号 16 位目标值，高字节在前 |
| 3-4 | 右电机有符号 16 位目标值，高字节在前 |
| 5 | 校验和：前 5 字节相加后保留低 8 位 |

示例：默认速度闭环下，左电机目标 `+1000 RPM`、右电机目标 `-1000 RPM`：

```text
A5 03 E8 FC 18 A4
```

目标值含义取决于 `FOC_MODE`：开环模式是有符号占空比指令（文档约定 0-10000 对应 0-100%）；速度模式单位为 RPM；角度模式单位为编码器计数。源码默认 `FOC_MODE` 为速度环。

当前默认启用速度数据回传。回传字段由 `DATA_PRINTF`、`VECOCITY_PRINTF`、`ANGLE_PRINTF` 等宏控制；默认输出左右电机滤波速度以及结束字段 `0`，并以逗号分隔、CRLF 结尾。输出由 TIM3 中断调用，源码注释目标周期为 1 ms。切换回传字段后，上位机解析格式也要同步调整。

## 编译与下载
0. 第一次使用的时候(这时候芯片flash里面没东西)记得在driver_config.h里面把FIRST_USE改为YES，烧录程序(烧录程序配置不能设置为全片擦除),然后再把FIRST_USE改为NO后再烧录回去即可。
1. 安装与该工程兼容的 MounRiver Studio（工程生成文件标记 MRS 1.9.2）。
2. 在 MounRiver Studio 中导入 `驱动代码/CH32V203C8T6 FOC双驱/Double_FOC.wvproj`。
3. 检查 `Software/driver_config.h` 中的电机使能、控制模式、电流采样类型和保护选项；根据电机及板卡实测参数校准 PID、极对数、方向和零点。
4. 执行 Build。工程生成文件位于工程的 `obj/` 目录，包含 `Double_FOC.elf`、`Double_FOC.hex` 等构建产物。
5. 使用与 CH32V203 兼容的 WCH 调试/下载器连接板上调试接口，通过 MounRiver Studio 下载并调试。首次连接前核对调试器型号、接口针脚定义和电平。

工程配置默认开启左右电机，但电池欠压保护、堵转保护和看门狗均在 `driver_config.h` 中关闭。首次上电前请检查这些保护是否满足你的实际应用要求。

## 校准与调试建议

- 首次转动前，确认相线顺序、编码器安装方向、极对数和电流采样极性；错误配置可能导致电机抖动、过流或失控。
- 按键扫描代码在检测到按键低电平并计数达到阈值时，会对启用的电机执行零点校准并写入 Flash。按键 GPIO 的文档与源码存在冲突，先确认板上实际接线。
- 先不连接机械负载，以限流电源和低目标值验证单路电机，再逐步验证双路。不要在通电时插拔电机相线或调试线。
- 若串口无响应，先核对板卡 UART 实际引脚、共地、波特率和 6 字节校验和；UART 引脚当前存在上述源码/文档冲突。

## AI辅助发现的原有代码错误

以下整理自电流环、ADC/PWM 时序和角度/速度环排查对话，修正状态于 2026-10-12 对照当前源码核查。“已修正”表示代码已落实对应修改，不代表所有控制模式均已完成板上验证。文件位置均相对于 `驱动代码/CH32V203C8T6 FOC双驱/`。

### 最初发现的六项问题

| 原有问题 | 影响及示例 | 当前修正情况 | 文件位置 |
| --- | --- | --- | --- |
| 圆限幅混用有符号与无符号运算 | 模长 `sum` 为 `uint32_t`，负电压指令参与无符号除法后可能变成很大的正数。例如 `uq=-3000、ud=3000` 时，原结果约为 `+1009589`，正确结果应约为 `-2896`。 | 已修正：平方和使用 `uint64_t`，缩放乘除使用有符号 `int64_t`，保留轴方向；模长向上取整，避免缩放后越过圆限幅。 | `Software/foc.c` |
| dq 电流变换归一化系数少了约两倍 | 查表幅值为 1000，原两相公式除以 1732，反馈约为常规幅值不变变换的一半。电角度为 0、`Ia=1000mA、Ic=-500mA` 时，原 AC 公式得到 `Id≈500mA`，应约为 `1000mA`。 | 已修正比例：两相公式分母改为 866，三相公式分母由 3000 改为 1500。采样极性、相序及编码器零点仍需实测确认。 | `Software/inline_current.c` |
| PI 积分每步丢弃小数，形成死区和正负不对称 | 原代码先右移再累加。`Ki=0.008` 转为 524 后，持续 `+100mA` 误差的稳态每步积分增量为 0；算术右移下，`-100mA` 却为 -1。 | 已修正：使用 `int64_t integral_acc` 保留积分小数，按相同尺度限幅，仅生成输出时除以 `131072`，采用向零截断。 | `Software/pid.c`、`Software/pid.h` |
| ADC 启动转换后立即读取，且电池采样会额外触发 | 未等待整组 DMA 完成，可能读到上一轮或不同批次混合的数据；电池读取干扰电流采样节奏。 | 已修正读取流程：运行时由控制中断统一启动扫描，检查整组 DMA 完成后发布独立快照；两路电流和电池读取已发布结果。控制中断不阻塞等待，通常使用前一控制周期触发的数据；电流模式缺帧时跳过 PI 并输出零相间电压。PWM 硬件同步尚待完善。 | `Hardware/driver_adc.c`、`Software/motor_control.c`、`Software/inline_current.c` |
| PWM 比较值重复偏置、缩放，且三相更新缺少预装载 | FOC 已输出约 `0～4000` 的比较值，底层再执行 `(4000+duty)/2`，导致相间电压幅度减半；逐相立即写入可能影响当前 PWM 周期。 | 已修正：直接写入比较值，TIM2/TIM4 三个通道均启用预装载；写入整组三相值期间暂时禁止更新事件，完成后恢复原状态，使其在后续更新事件统一生效。 | `Hardware/pwm_output.c` |
| 串口负目标值解析错误 | 原写法在拼接前转换高字节，不能完成整体 16 位符号解释；`FF 9C` 应为 -100，却得到 65436。 | 已修正：先用 `uint16_t` 拼接，再整体转为 `int16_t`。纯电流模式的目标电流限幅仍未补齐。 | `Software/motor_uart.c` |

### 后续排查发现的问题

| 原有问题 | 影响 | 当前修正情况 | 文件位置 |
| --- | --- | --- | --- |
| ADC 实际时钟与注释不符，超出规格范围 | 在原 144MHz 系统配置下，APB2 未分频，ADC 六分频实际为 24MHz，并非注释中的 12MHz。 | 已修正当前 144MHz HSE 配置：APB2 二分频为 72MHz，ADC 六分频为 12MHz。TIM1 因 APB 分频后的定时器倍频机制仍为 144MHz，原 20kHz 控制周期无需随之修改。 | `User/system_ch32v20x.c`、`Hardware/driver_adc.c` |
| 串口相关中断可能阻塞电流环 | TIM3 内阻塞式打印原先与 TIM1 同抢占级，USART1 接收优先级又高于 TIM1，可能延迟 50μs 周期的控制任务。 | 已调整：TIM1 抢占优先级为 0，TIM3 和 USART1 为 1。用户反馈间歇噪声可能与该阻塞有关；打印本身仍是阻塞式，不能据此认定所有噪声均已解决。 | `Hardware/pwm_output.c`、`Hardware/serial.c`、`Debug/debug.c` |
| 三环角度模式未纳入串口目标解析 | `ANGLE_VECOCITY_CURRENT_LOOP_MODE` 不在原角度解析分支内，串口不能正常更新该模式的目标角度。 | 已修正：加入角度目标解析分支。 | `Software/motor_uart.c` |
| 速度方向与角度方向定义不一致 | 原速度固定取负号，角度却使用 `rotation_direction`；某些方向配置下，两者符号不一致。 | 已修正：角度累计和速度计算统一使用经过 `rotation_direction` 修正的 `angle_delta`。 | `Software/motor_control.c` |
| 速度换算未使用实际观测周期，整数滤波丢失低速信息 | `20000/6000` 的整数分频得到 3，实际观测频率约为 6666.7Hz；按 6000Hz 换算并提前截断系数会产生比例误差，整数滤波还会抑制较小速度反馈。 | 已修正：按 `F_OPEN/VECOCITY_OB_COUNT` 的实际周期进行 64 位换算，使用 Q16 滤波状态保留小数，输出时再转换为整数 RPM。 | `Software/motor_control.c`、`Software/motor_control.h` |
| SVPWM 零矢量分支与邻近指令的共模占空比不连续 | 原默认分支输出三相全 0，邻近的小指令在七段式调制下接近三相 50%，可能引入共模跳变；两者理想相间电压均为零，不能直接等同于转矩冲击。 | 已调整：默认分支三相统一输出计算得到的 `svpwm.ta`，七段式零指令对应居中占空比。 | `Software/foc.c` |

### 尚待处理或验证的事项

- **纯电流目标限幅**：`I_Q_LOOP_MODE`、`I_D_LOOP_MODE` 的串口目标目前直接赋值，需结合电机及驱动能力补充范围限制；PI 输出限幅不等于目标电流限幅。
- **采样与 PWM 同步**：整帧 DMA 发布解决了数据完整性问题，但目前仍由控制中断软件触发 ADC，尚未建立固定 PWM 相位的硬件触发采样。
- **积分参数与饱和处理**：当前 `Ki` 是每次调用的离散积分系数，未显式乘控制周期不必然是错误；改变环路频率时需重新换算。现有积分限幅也不等于针对最终电压饱和的完整抗积分饱和处理。
- **修正电流换算注释**：`inline_current.c` 中仍有旧的 `38>>16` 说明。`38/65536` 近似 `1/1732`，不再对应当前两相公式的 `1/866`。
- **角度附近振荡仍需定位**：空载振荡、加负载后减小是观察现象，尚不能确定由限幅、增益、时延或阻尼中的哪一项主导。角度到电流采用 P 环本身不是代码错误；增加速度阻尼属于控制方案和调参选择，不列为已确认的原有错误。
- **速度模式回传电流为 0 尚未确认是故障**：需区分实际 `i_q/i_d`、电流目标 `i_q_set` 和串口末尾固定字段 `0`；电压型速度模式不使用电流目标，不能仅凭该值判断采样异常。
